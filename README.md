# Docker-шлюз VLESS

Скопируй шаблон командой `cp .env.example .env` и укажи в `.env` свою ссылку целиком в одинарных кавычках:

```dotenv
SUBSCRIPTION_URL='https://example.org/sub/твой-токен'
```

Запусти `docker compose up -d --build`. При каждом старте шлюз скачивает подписку. Если доступны несколько поддерживаемых профилей и имя сервера пустое, Xray параллельно проверяет HTTPS-доступ через каждый из них с интервалом 10 секунд. Новые соединения идут через доступный сервер с наименьшей измеренной задержкой. Пока нет успешных проверок, Xray пробует первый профиль. Открытые соединения остаются на выбранном сервере. При его отказе приложение должно переподключиться. Чтобы закрепить сервер, добавь в `.env` строку `SUBSCRIPTION_SERVER='точное имя из подписки'`. Чтобы скачать изменения по той же ссылке, выполни `docker compose restart vpn-client`.

Поддерживаются списки VLESS-ссылок в тексте и Base64, а также JSON-профили Xray с самостоятельным VLESS outbound. Из JSON импортируются настройки исходящего соединения. Для одиночной ссылки по-прежнему можно указать `VLESS_URL='vless://...'`. При заполнении обеих переменных используется подписка.

Используется существующая сеть `vpn-network`. На новом сервере один раз создай её командой `docker network create vpn-network`.

## Подключение другого контейнера

В Compose приложения добавь общую сеть, сохранив сети, через которые приложение общается со своими сервисами. Для приложений, поддерживающих настройки прокси через окружение:

```yaml
services:
  app:
    # остальные параметры твоего сервиса
    networks: [default, vpn-network]
    environment:
      http_proxy: http://vpn-client:1080
      https_proxy: http://vpn-client:1080

networks:
  vpn-network:
    external: true
```

Если у приложения есть отдельная настройка HTTP-прокси, укажи там `http://vpn-client:1080`. После смены настроек выполни `docker compose up -d` в проекте приложения. Tinyproxy принимает HTTP и HTTPS CONNECT на 1080 и передаёт запросы локальному Xray на 8123. Приложение должно поддерживать HTTP-прокси. Порт на хосте не публикуется.

Проверка со стороны другого контейнера:

```sh
docker run --rm --network vpn-network curlimages/curl -fsSx http://vpn-client:1080 https://checkip.amazonaws.com
```

Ответ должен содержать выходной IP VLESS-сервера. Как в прежней конфигурации, Tinyproxy разрешает клиентов из 172.16.0.0/12. Если у сети другой CIDR, добавь его в `tinyproxy.conf` как `Allow` и выполни `docker compose up -d --build`.

Поддерживаются ссылки VLESS с базовыми настройками TCP/raw, WebSocket, gRPC и XHTTP. При неизвестном параметре шлюз выводит его название в `docker compose logs vpn-client`.
